Buckets are the fundamental containers for objects in MinIO. This page covers creating and managing buckets with the MinIO Client (`mc`), as well as configuring versioning, event notifications, object lock (WORM), tagging, and storage quotas.

## Creating and listing buckets

Use `mc mb` to create a new bucket.

```sh
mc mb myminio/mybucket
```

To create a bucket with object locking enabled (which also enables versioning), pass the `-l` / `--with-lock` flag. Object locking **must** be configured at creation time and cannot be enabled on an existing bucket.

```sh
mc mb --with-lock myminio/mybucket
```

List all buckets on an alias:

```sh
mc ls myminio
```

List objects (recursively) inside a bucket:

```sh
mc ls --recursive myminio/mybucket
```

Delete an empty bucket:

```sh
mc rb myminio/mybucket
```

<Warning>
  Deleting a versioned bucket requires all versions, including delete markers, to be removed first. You cannot remove a bucket that still contains objects or versions.
</Warning>

Force-remove a bucket and all its contents:

```sh
mc rb --force myminio/mybucket
```

## Versioning

Versioning keeps multiple copies of an object in the same bucket. Each PUT creates a new version with a unique UUID version ID generated by MinIO. Deleting an object without specifying a version ID adds a delete marker rather than permanently removing data.

<Note>
  Versioning is only available in erasure-coded and distributed erasure-coded deployments. It is not available in single-drive or gateway deployments.
</Note>

### Enabling and suspending versioning

```sh
# Enable versioning
mc version enable myminio/mybucket

# Suspend versioning (existing versions are preserved)
mc version suspend myminio/mybucket

# Check versioning status
mc version info myminio/mybucket
```

Versioning states:

| State | Behavior |
|---|---|
| Unversioned (default) | All objects have a `null` version ID. |
| Enabled | Every PUT creates a new version. DELETE adds a delete marker. |
| Suspended | New PUTs overwrite the `null` version. Existing versions are preserved. |

### Excluding prefixes from versioning

MinIO extends the S3 versioning specification to allow specific prefix patterns to be excluded from versioning. Objects matching these patterns behave as though versioning were suspended and are not replicated.

```xml
<VersioningConfiguration xmlns="http://s3.amazonaws.com/doc/2006-03-01/">
  <Status>Enabled</Status>
  <ExcludedPrefixes>
    <Prefix>*/_temporary</Prefix>
  </ExcludedPrefixes>
  <ExcludedPrefixes>
    <Prefix>*/__magic</Prefix>
  </ExcludedPrefixes>
  <!-- up to 10 prefixes total -->
</VersioningConfiguration>
```

<Tip>
  Prefix exclusions are useful for Spark/Hadoop workloads that write temporary files to prefixes like `_temporary` or `__magic` during job execution.
</Tip>

## Object lock and WORM

Object lock enforces Write-Once-Read-Many (WORM) immutability on objects. It prevents deletion or overwrite until a configured retention period expires. Object locking requires the bucket to be created with `--with-lock` and automatically enables versioning.

### Retention modes

| Mode | Description |
|---|---|
| `GOVERNANCE` | Authorized users with `s3:BypassGovernanceRetention` can delete or shorten retention periods. |
| `COMPLIANCE` | No one—including root—can delete an object before the retention period expires. |

### Setting a default bucket retention policy

```sh
mc retention set --default governance 30d myminio/mybucket
```

This applies a 30-day Governance retention period to all new objects written to the bucket.

### Setting per-object retention via the AWS CLI

```sh
aws s3api put-object \
  --bucket mybucket \
  --key myobject \
  --object-lock-mode GOVERNANCE \
  --object-lock-retain-until-date "2027-01-01" \
  --body /path/to/file
```

### Legal hold

A legal hold is independent of retention mode and duration. An object under legal hold cannot be deleted until the hold is explicitly removed.

```sh
aws s3api put-object \
  --bucket mybucket \
  --key myobject \
  --object-lock-legal-hold-status ON \
  --body /path/to/file
```

<Warning>
  In `COMPLIANCE` mode, the retention date cannot be shortened by anyone. Plan retention windows carefully before enabling compliance mode in production.
</Warning>

## Bucket notifications

MinIO can publish events triggered by object operations to external targets. Supported targets include:

<Tabs>
  <Tab title="Messaging">
    - AMQP (RabbitMQ)
    - MQTT
    - NATS
    - Apache Kafka
    - NSQ
  </Tab>
  <Tab title="Databases">
    - Redis
    - Elasticsearch
    - PostgreSQL
    - MySQL
  </Tab>
  <Tab title="HTTP">
    - Webhooks
  </Tab>
</Tabs>

### Supported event types

| Category | Events |
|---|---|
| Object | `s3:ObjectCreated:*`, `s3:ObjectRemoved:*`, `s3:ObjectAccessed:*` |
| Replication | `s3:Replication:OperationCompletedReplication`, `s3:Replication:OperationFailedReplication` |
| ILM Transition | `s3:ObjectRestore:Post`, `s3:ObjectRestore:Completed` |
| Global | `s3:BucketCreated`, `s3:BucketRemoved` |

### Configuring a notification target

<Steps>
  <Step title="Configure the notification target">
    Add the target endpoint to MinIO server configuration. For example, to add a Kafka endpoint:

    ```sh
    mc admin config set myminio notify_kafka:1 \
      brokers="localhost:9092" \
      topic="minio-events"
    ```

    Restart MinIO to apply the configuration. On startup, the server will print the ARN for the configured target (e.g., `arn:minio:sqs::1:kafka`).
  </Step>
  <Step title="Enable notifications on the bucket">
    Use `mc event add` to subscribe to events on a bucket:

    ```sh
    mc mb myminio/images
    mc event add myminio/images arn:minio:sqs::1:kafka --suffix .jpg
    ```
  </Step>
  <Step title="Verify the configuration">
    ```sh
    mc event list myminio/images
    ```
  </Step>
</Steps>

### Inspecting available notification targets

```sh
mc admin config get myminio | grep notify
```

This lists all configured notification subsystems (e.g., `notify_kafka`, `notify_postgres`, `notify_webhook`).

## Bucket tagging

Tags are key-value pairs attached to a bucket and can be used as filters in lifecycle and replication rules.

```sh
# Set tags on a bucket
mc tag set myminio/mybucket "environment=production&team=storage"

# List tags on a bucket
mc tag list myminio/mybucket

# Remove tags from a bucket
mc tag remove myminio/mybucket
```

Tags can also be applied to specific object versions:

```sh
mc tag set --version-id <versionID> myminio/mybucket/myobject "key=value"
```

## Bucket quotas

MinIO supports **hard quotas** that prevent writes once the configured storage limit is reached.

```sh
# Set a hard quota of 1 GB
mc admin bucket quota myminio/mybucket --hard 1gb

# View current quota configuration
mc admin bucket quota myminio/mybucket

# Remove quota configuration
mc admin bucket quota myminio/mybucket --clear
```

<Info>
  Quotas are enforced at the bucket level. Objects already stored in the bucket are not deleted when a quota is set; only new writes are blocked once the limit is reached.
</Info>

## Summary of mc commands

| Command | Description |
|---|---|
| `mc mb <alias>/<bucket>` | Create a bucket |
| `mc mb --with-lock <alias>/<bucket>` | Create a bucket with object locking enabled |
| `mc ls <alias>` | List buckets |
| `mc rb <alias>/<bucket>` | Remove an empty bucket |
| `mc rb --force <alias>/<bucket>` | Force-remove a bucket and contents |
| `mc version enable <alias>/<bucket>` | Enable versioning |
| `mc version suspend <alias>/<bucket>` | Suspend versioning |
| `mc version info <alias>/<bucket>` | Show versioning status |
| `mc retention set --default <mode> <duration> <alias>/<bucket>` | Set default object lock retention |
| `mc event add <alias>/<bucket> <arn>` | Subscribe bucket to a notification target |
| `mc event list <alias>/<bucket>` | List notification subscriptions |
| `mc tag set <alias>/<bucket> "<key>=<value>"` | Set bucket tags |
| `mc tag list <alias>/<bucket>` | List bucket tags |
| `mc admin bucket quota <alias>/<bucket> --hard <size>` | Set a hard quota |
